# 交易 Agent × StockManager 初版验收

## 本地启动

两个仓库都切到 `codex/agent-paper-integration` 分支，先按各自的环境说明安装依赖，再在 TradingAgents 仓库执行：

```bash
./scripts/dev.sh start
./scripts/dev.sh status
```

四项服务均显示运行后，打开 `http://localhost:5173/chat`。结束试用时运行 `./scripts/dev.sh stop`。模型与数据源密钥按 `.env.example` 配置；缺少某项凭据时，对应取证能力会显示不可用。

## 建议的人工验收顺序

1. **Agent 工作台**：新建普通对话，查询明确的 A 股代码。核对计划步骤、证据来源和基准日；刷新页面后确认任务与消息仍在。缺少代码的买卖问题应要求补充代码。
2. **模拟盘与账户范围**：打开一个单策略模拟盘，从账本进入 Agent，查询权益、现金、近期成交；在工作台继续同一对话，再回到账本。切换到另一账户后，旧账户数据不能作为新账户证据。
3. **组合与子策略**：从组合决策卡进入已验证归属的子策略账本，再返回父组合。子策略可以查看和提问，推进操作只在父组合发起。
4. **审批与回执**：在测试账户提出“推进模拟盘到 YYYY-MM-DD”，核对提案账户、日期和权益后确认；刷新页面，核对任务回执与账本日期。重复确认不能产生第二个作业。建议先用虚构账户执行，不要直接重置或删除现有账户。
5. **证据缺口**：断开 MCP 或提出“现在还能卖出吗”，核对 Agent 明确说明缺少数据或成交条件，不给出可执行的交易判断。历史公告关键词零命中也不能解释为没有风险公告。
6. **界面**：在桌面和手机视口检查任务列表、中央对话、证据抽屉以及模拟盘的 Agent/账本跳转；明暗主题均应可读。

## 初版边界

- Agent 可读取证据、分析、提出模拟盘推进提案；写账本需用户针对该提案确认。没有逐笔模拟下单或实盘下单能力。
- “能否成交”还缺停牌、涨跌停、交易日和账户可交易数量等权威检查工具，因此 Agent 会停止在证据缺口处。
- 更丰富的失败后重规划、Skill 内部检查点续跑和完整交易规则引擎属于后续阶段。外部行情、公告和模型质量仍需使用实际数据持续验收。
- 现有真实账户没有发送给外部模型；真实模型联调使用临时虚构账户。用户对实际账户开启模型回答前，应自行确认数据与模型服务配置。

详细架构与逐项验收记录见 [TRADING_AGENT_HARNESS_DESIGN.md](TRADING_AGENT_HARNESS_DESIGN.md)。
