# 策略记忆使用与验收

## 用户能看到什么

- 工作台执行区：正在检索经验 → 找到适用经验 → 正在核对条件 → 模型报告参考/不适用。
- 没有可用经验：明确提示依据当前数据分析。检索或回答生成失败时保留记录，不冒充已使用。
- 任务档案：检索数、实际提供数、截止日期、经验快照、适用范围、样本数、模型报告的理由。
- 候选及个股分析：保存并展示同样的经验详情；个股最终组合决策通过结构化字段报告参考情况，旧模型的纯文本回退则显示未报告。
- 反思页：可用、待批准、停用、过期经验的数量；最近 200 个工作台任务的使用概览；经验的历史版本和批准记录；最近一次成对评测。
- 关联案例：原始信号日期、观察周期、收益/超额数值及归因。能找到不同结果时优先保留对照；每条经验最多提供两个案例。

先在反思页查看候选的原始案例和适用条件，再批准希望用于后续判断的经验。只有已批准、仍有效、在分析截止日已知的经验能够进入上下文。没有匹配经验是正常状态。

## 记忆生命周期

1. 决策按观察周期到期后复盘，原始输入、实际结果和新增事件分开保存。
2. 反思/跨标的挖掘产生候选经验，先不参与判断。成功、失败、中性规避/错失机会均保留原始案例。
3. 人工批准当前版本，冻结其支撑案例摘要；之后案例清理或修正不覆盖这次批准的案例快照。
4. 问题按股票、行业、交易板块、因子、风格、场景和日期检索，最多选取五条。相同内容去重，相反方向的机会成本/风险规避经验保留并提示核对差异。
5. 模型接收历史资料后报告 `referenced` / `not_applicable` 和理由。服务端只接受实际提供的 ID。
6. 经验停用、过期或挖掘更新后停止用于当前分析；挖掘更改内容或统计依据时重新等待批准。重复处理同一集合不增加证据数。

## 版本与时间边界

SQLite 的 `strategy_lesson_versions` 表和插入/更新触发器记录内容、样本、适用条件及治理状态。迁移只保存已有行的最后已知版本；无法还原迁移前的更早文本或批准过程。重新打开数据库不会重复迁移。

历史分析使用北京时间该日结束前的最后版本，包括当时有效、后来停用的经验。未批准经验不能因之后获批而提前进入历史分析；关联案例也必须已完成且当时可得。旧 Markdown 反思没有完成时间时仍可查看，但不进入带日期的分析上下文。

工作台经验如果早于行情取证，会在回答前重新对齐到最终证据日期；上下文预算不足时减少经验条数，保留有效 JSON，记录实际提供的集合。

`memory_trace` 中的提供记录和模型报告均是可追踪的上下文使用信息，不能证明模型内部如何思考或判断质量提高。策略权限与硬约束由服务端执行，历史文本没有授予权限的作用。

## 成对评测工具

`core/memory_evaluation.py` 在相同冻结候选上分别运行有/无记忆复核，按历史日期检索版本，交替两组调用顺序，分别创建复核器，不读取新行情。事后超额仅用于评分，不传入模型；相同股票/日期的重复样本会被拒绝。评测不写入持仓、决策、反思样本，也不自动批准经验。

输入 JSON 是数组，每个样本包含：

```json
{
  "trade_date": "YYYY-MM-DD",
  "snapshot_as_of": "YYYY-MM-DD",
  "candidate": {
    "symbol": "股票代码",
    "industry": "行业",
    "quant_score": 70,
    "factor_scores": {},
    "data_coverage": {},
    "risk_flags": []
  },
  "excess_return": 0.01
}
```

以上为字段说明，数值是示例。候选必须是信号时点已保存的输入，不能用事后重新获取的候选冒充冻结数据。`excess_return` 为观察周期后的实际超额，采用小数口径。

本地显式运行（会调用指定外部模型，先核对输入内容）：

```bash
.venv/bin/python scripts/evaluate_strategy_memory.py \
  --input /path/to/frozen-snapshots.json \
  --output /path/to/memory-report.json \
  --db-path /path/to/app.db \
  --provider deepseek --model YOUR_MODEL_ID \
  --style medium_term --save-report
```

输出包括两组方向命中率、覆盖率、判断改变数、方向超额代理及近似区间、每条样本的理由和经验快照。无匹配经验的样本不计入效果比较，少于 20 对适用样本时显示不足。方向超额不是账户收益；区间未消除同日/同股相关性，需重复运行和分组评测后再做策略结论。

`--save-report` 仅将报告存入产物库。反思页展示最新报告，产物库的“记忆评测”可查看逐条比较。尚未跑模型评测时展示“尚无报告”，不把开发测试的合成数据当作真实评测。

## 验收路径

1. 打开反思页，展开经验详情、原始案例、版本记录；批准或停用一条经验后数量应刷新。
2. 在工作台提出相关行业/个股分析问题，观察执行提示，打开任务档案检查截止日期和参考理由。
3. 刷新对话，确认进度和经验记录仍在；没有适用经验或模型未报告理由时应如实显示。
4. 展开选股候选/个股分析，查看案例数值和参考理由。长文本折叠，侧栏独立滚动。
5. 通过隔离的冻结样本运行成对评测，检查反思页和产物库的报告；在样本不足时保持“尚不能判断效果”的状态。
