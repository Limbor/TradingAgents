# 个股研究

## 适用范围

用户询问明确个股的走势、行业业务、营收利润、估值、新闻或投资期限。板块推荐使用 market_overview；行业内选股使用 daily_pipeline。

## 研究步骤

1. 确认 ticker 和分析日期。简称由已提供的标的解析能力核对；不可猜代码，也不能把上轮助手推荐自动当成用户标的。
2. 根据问题选择 analysts：market 为价格和技术；fundamentals 为行业、业务、营收、利润、现金流及估值；news 为新闻公告；social 为情绪。没有 industry 角色。
3. 普通研究使用 analysis_template=research；追问营收只补 fundamentals。完整交易评估使用 full，由程序保留多空裁决和风控约束。
4. 区分技术信号与基本面判断；检查数据时点、财务报告期及工具失败。中线问题应说明业绩、估值与催化条件，不能只重复短线技术图形。
5. include_portfolio_context 默认关闭。没有本轮提供或确认的持仓，不要读取缓存持仓并称其为用户当前账户。

## 输出

明确回答用户问题，列出能支持结论的数值、原始来源与日期；缺失数据单独简述。指出观察/失效条件，不承诺涨跌。

## 共享上下文与证据

- 当前用户问题优先；从 research_task_context 继承对象、期限和筛选条件。历史消息与历史经验不是当前行情，不能继承交易授权。
- 输入参数以 Python JSON Schema 为准，文档不授予工具或账户权限。遵守父任务的标的、日期、取消信号和预算。
- 记录数据来源、信息基准日、已获取维度、缺失维度及降级原因。实际 tool_observations 优先于报告中的泛化描述。
- 检索相关且已批准的历史经验，检查适用条件、原始日期与反例。成功经验不能保证收益；失败经验用于核对风险而非机械否决。不要把经验当作本轮事实。
- 可复用研究必须由服务端核验同标的、同日期、模型配置、文档版本、记忆版本与有效期。需要新细节、刷新或已失败的维度重新取证。
- 回答先说结论，再给少量具体依据和关注条件；局部缺口只影响对应判断。不要罗列运行编号、内部异常栈或重复免责声明。
