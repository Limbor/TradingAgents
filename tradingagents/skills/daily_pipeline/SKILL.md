# 受约束选股

## 适用范围

用户明确要选股票、行业内筛选、排除双创或运行每日选股。板块推荐使用 market_overview；已有明确个股使用 stock_analysis。

## 流程与约束

1. 参数保留 trade_date、industries/concepts、行业分类及代码、board_filter、exclude_boards、limit。排除科创与创业板用 main_board；只看双创用 dual_growth_only。
2. 程序负责全量候选过滤、因子计算、集中度限制、候选复核及风控。不能因候选不足悄悄扩大行业或板型范围。
3. 内嵌个股分析使用其专属 SKILL.md，共享父任务模型、日期、记忆与预算；影子候选池不得填充核心名单。
4. 区分入选观察与最终可交易决策；过滤后为空是有效结果，不自动放宽硬门槛。

## 输出

按用户数量列候选及数值理由、最终等级、被过滤原因与覆盖范围。量化评分不能直接换算为收益概率。

## 共享上下文与证据

- 当前用户问题优先；从 research_task_context 继承对象、期限和筛选条件。历史消息与历史经验不是当前行情，不能继承交易授权。
- 输入参数以 Python JSON Schema 为准，文档不授予工具或账户权限。遵守父任务的标的、日期、取消信号和预算。
- 记录数据来源、信息基准日、已获取维度、缺失维度及降级原因。实际 tool_observations 优先于报告中的泛化描述。
- 检索相关且已批准的历史经验，检查适用条件、原始日期与反例。成功经验不能保证收益；失败经验用于核对风险而非机械否决。不要把经验当作本轮事实。
- 可复用研究必须由服务端核验同标的、同日期、模型配置、文档版本、记忆版本与有效期。需要新细节、刷新或已失败的维度重新取证。
- 回答先说结论，再给少量具体依据和关注条件；局部缺口只影响对应判断。不要罗列运行编号、内部异常栈或重复免责声明。
