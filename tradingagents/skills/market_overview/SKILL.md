# 市场与板块研究

## 适用范围

板块推荐、行业强弱、主题机会、大盘环境。接续“重新推荐一个”时继承用户上一轮的板块对象，调整数量，不切换成选股。

## 研究步骤

1. 获取对应交易日的指数、量能及行业/概念横截面。使用 focus_industries 限定关注方向，保持行业分类口径。
2. 比较 industry_stances 中涨跌、资金、估值、趋势与风险；概念和一级行业必须区分。宽行业代理不能冒充细分板块本身。
3. 优先从当期完整证据中选观察方向。单日排名说明单日表现；长期或中线判断需要额外时序/基本面支持。
4. 若摘要有省略，通过 read_task_evidence 分页读已保存的字段；不要因压缩判定数据没有获取。RunManager 清单及历史复盘不能代替当期行业数据。

## 输出

按用户数量给方向、当期依据、后续关注指标与主要风险，先结论后表格。无当期行业数据时说明具体缺口并补查询，不能把个股名单的行业分布当成板块排名。

## 共享上下文与证据

- 当前用户问题优先；从 research_task_context 继承对象、期限和筛选条件。历史消息与历史经验不是当前行情，不能继承交易授权。
- 输入参数以 Python JSON Schema 为准，文档不授予工具或账户权限。遵守父任务的标的、日期、取消信号和预算。
- 记录数据来源、信息基准日、已获取维度、缺失维度及降级原因。实际 tool_observations 优先于报告中的泛化描述。
- 检索相关且已批准的历史经验，检查适用条件、原始日期与反例。成功经验不能保证收益；失败经验用于核对风险而非机械否决。不要把经验当作本轮事实。
- 可复用研究必须由服务端核验同标的、同日期、模型配置、文档版本、记忆版本与有效期。需要新细节、刷新或已失败的维度重新取证。
- 回答先说结论，再给少量具体依据和关注条件；局部缺口只影响对应判断。不要罗列运行编号、内部异常栈或重复免责声明。
