# 轻量个股筛选

## 适用范围

用户要快速发现个股候选，可用 theme 限定行业/主题；不适用于板块排名。需要严格板型/成分范围、完整交易评估时使用 daily_pipeline。

## 流程

程序先量化排名，再执行候选复核、风险过滤及排序。候选分数不是买入决定。明确 theme、market 和 limit，展示排除原因、观察等级与数据缺口；不以历史经验代替实测因子。

## 输出

精简候选表：标的、行业、关键因子、关注理由和风险。0% 仓位或跳过等级不得包装成买入建议。

## 共享上下文与证据

- 当前用户问题优先；从 research_task_context 继承对象、期限和筛选条件。历史消息与历史经验不是当前行情，不能继承交易授权。
- 输入参数以 Python JSON Schema 为准，文档不授予工具或账户权限。遵守父任务的标的、日期、取消信号和预算。
- 记录数据来源、信息基准日、已获取维度、缺失维度及降级原因。实际 tool_observations 优先于报告中的泛化描述。
- 检索相关且已批准的历史经验，检查适用条件、原始日期与反例。成功经验不能保证收益；失败经验用于核对风险而非机械否决。不要把经验当作本轮事实。
- 可复用研究必须由服务端核验同标的、同日期、模型配置、文档版本、记忆版本与有效期。需要新细节、刷新或已失败的维度重新取证。
- 回答先说结论，再给少量具体依据和关注条件；局部缺口只影响对应判断。不要罗列运行编号、内部异常栈或重复免责声明。
